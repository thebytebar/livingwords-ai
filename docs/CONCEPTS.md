# Architecture and concepts

LivingWords is local desktop AI with trusted, private workflows for serious users: a private AI for writing, thinking, planning, and software tasks, built around a pretrained Gemma model:

- **Model:** Gemma 4 E2B Instruct provides language ability; the project does not pretrain or fine-tune model weights.
- **Inference:** Electron desktop builds run the model through a bundled `llama.cpp` runtime on macOS, Windows, and Linux.
- **Interfaces:** the desktop app is the supported product; there is no CLI or HTTP web interface.
- **Workflows:** general-purpose chat with a Christian persona informed by historic Trinitarian Christianity and the Bible, plus a built-in terminal for software tasks. The Christian perspective is used when relevant to faith, theology, and ethics, not forced into unrelated answers. Assistant-proposed terminal commands require user approval before they run.
- **Conversation context:** the Electron app stores chat sessions locally and supplies a bounded history from the selected conversation when generating follow-up answers.
- **Local documents:** each conversation can reference code, configuration, and other text files or text-based PDFs and folders in place. The assistant searches locally on demand and adds bounded relevant excerpts to context. The Documents panel records how passages entered context and shows the bounded excerpt, source location, and access method when available; this reports what was supplied to the model, not what it necessarily relied on while reasoning. Citation links open the document viewer; users can remove references and approve proposed text-file edits after reviewing a diff. PDFs are read-only. Deleting a conversation removes references and derived indexes, never the originals. Scanned PDFs and OCR are not supported.
- **Privacy:** inference runs locally on the device, and conversation data is stored locally; the Electron renderer cannot access Node.js or the filesystem directly.
- **Cost model:** there is no account, subscription, or per-prompt cloud fee. Users provide the hardware, storage, and power needed to run the model.

The desktop client bundles its pinned GGUF model into each Electron build. `npm install` downloads and verifies the model into the ignored project model cache before the build injects it into app resources. The installed app does not download weights on first launch. See the [desktop build guide](DESKTOP.md) for artifact pins and release caveats.

## Memory profile

The desktop Settings window offers 8K, 16K, 32K, 64K, and 128K context windows, with 32K as the default. The response limit is approximately one quarter of the selected window, rounded down to the nearest 1,000 tokens and capped at 10,000. Larger contexts use more memory; changing the context restarts the local inference runtime and cancels any active response.

## Scope and local data

Chat prompts are processed by the bundled local model. Conversation-owned references, extracted text, and indexes stay in the app's local user-data directory; they are not sent to a cloud service. A conversation can search only its own referenced files and folders. Folder indexing is recursive with no 100-file cap; bulk indexing skips hidden entries except `.github/copilot-instructions.md`, symlinks, `.gitignore` matches, and common generated/dependency folders. Individual files are limited to 20 MB, and derived text plus search indexes share a 250 MB cache budget across conversations. Inactive conversation caches are evicted least-recently-used and rebuilt when needed. Files outside the bulk index can be searched on demand within bounded file and byte limits; ignored/generated files are searched only when explicitly requested by the assistant. The local keyword index may miss passages phrased differently from the question. An attached folder adds a bounded depth-2 inventory (maximum depth 3, at most 200 entries) and up to 8 KB of recognized project guidance to context. The assistant can progressively list directories, read file pages (up to 2,000 lines or 50 KB), and grep within the folder under bounded result limits; it does not dump full folder contents into the prompt. Project guidance and retrieved document text are untrusted input. The Documents panel shows only folder files whose contents entered that conversation's model context; directory listings alone do not make a file appear there. The assistant can propose edits only to attached text files; the main process validates the reference, shows a diff for approval, and rejects stale proposals before writing. PDFs are read-only. External knowledge collections, scanned-PDF OCR, and automatic cross-conversation memory are not included. Existing `.livingwords/index.json` and desktop `index.json` files are ignored and left untouched. The selected context window and its corresponding response limit apply to each request.

The model is pretrained and is not fine-tuned by this project. It can make mistakes; verify answers when accuracy matters.
